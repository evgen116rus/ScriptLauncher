# ScriptLauncher — запуск PowerShell / BAT / CMD скриптов

GUI-приложение на C# (Windows Forms, .NET 11) для запуска
PowerShell-, BAT- и CMD-скриптов по кнопке, с произвольным списком скриптов.

## Возможности

- Список скриптов слева (любое количество, любых типов — PowerShell/.bat/.cmd
  вперемешку), с кнопками «Добавить», «Изменить», «Удалить» под списком.
- Справа — имя, путь и тип выбранного скрипта и кнопка «Запустить»
  (двойной клик по элементу списка тоже запускает скрипт).
- Окно можно свободно менять в размере (включая разворачивание на весь экран),
  а также двигать разделитель между списком и панелью справа.
- Список сохраняется в файл `%AppData%\ScriptLauncher\settings.json` и не
  теряется при закрытии и повторном запуске программы.
- Каждый скрипт запускается в **отдельном окне консоли**, а не внутри самой
  программы (через `powershell.exe` / `cmd.exe` с `UseShellExecute = true`).
- Приложение запрашивает права администратора при каждом запуске
  (через `app.manifest`, `requireAdministrator`) — поэтому и сами скрипты
  выполняются с правами администратора.

## Сборка и запуск

1. Установите .NET 11 SDK (https://dotnet.microsoft.com/download/dotnet/11.0),
   если его ещё нет. Если у вас другая версия, замените `net11.0-windows`
   на соответствующую (например, `net8.0-windows`) в `ScriptLauncher.csproj` —
   строго под ту версию, которую показывает `dotnet --list-sdks`, иначе
   сборка упадёт с ошибкой NU1100.
2. Откройте папку проекта в Visual Studio (File → Open → Folder), либо:

   ```
   dotnet build -c Release
   ```

3. Запустите `ScriptLauncher.exe` из `bin\Release\net11.0-windows\` напрямую
   (не через `dotnet run`), чтобы сработал запрос прав администратора.
4. Нажмите «Добавить», укажите путь к .ps1/.bat/.cmd файлу — тип скрипта
   определится автоматически по расширению (можно поменять вручную).
5. Выберите скрипт в списке слева и нажмите «Запустить» (или дважды
   щёлкните по нему).

## Структура проекта

- `Program.cs` — точка входа.
- `MainForm.cs` — главное окно: список скриптов слева, детали и запуск справа.
- `ScriptEditForm.cs` — диалог добавления/изменения одного скрипта.
- `AppSettings.cs` — модель списка скриптов, сохранение/загрузка JSON,
  перенос настроек со старой (однослотовой) версии программы.
- `app.manifest` — манифест с требованием прав администратора.

## Примечания

- Если у вас уже был настроен один из путей в старой версии программы
  (с тремя фиксированными слотами PowerShell/BAT/CMD), при первом запуске
  новой версии он автоматически попадёт в список.
- Для PowerShell используется `-ExecutionPolicy Bypass`, но только для
  конкретного запуска — политика выполнения в системе не меняется.
- Флаг `-NoExit` (PowerShell) и `/k` (cmd.exe) оставляют окно открытым
  после завершения скрипта. Чтобы окно закрывалось само, уберите `-NoExit`
  и замените `/k` на `/c` в `MainForm.cs` (метод `RunScript`).
- Если UAC-запрос при каждом старте мешает во время разработки, можно
  временно поставить в `app.manifest` `level="asInvoker"`.
